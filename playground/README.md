# Melbi Playground

Phase 0 introduces a WebAssembly worker that exposes the public Melbi API to the browser and a web-based playground for interactive testing.

## Quick Start

### Prerequisites

1. Install the WebAssembly target (one-time setup):
   ```bash
   rustup target add wasm32-unknown-unknown
   ```

2. Install `wasm-pack`:
   ```bash
   cargo install wasm-pack
   ```

3. Install Node.js dependencies:
   ```bash
   cd playground
   npm install
   ```

### Building & Development

1. Run the build script to compile tree-sitter WASM, WASM worker, and the web playground:
   ```bash
   cd playground
   bash scripts/build.sh
   ```

2. Preview the built playground locally:
   ```bash
   npm run preview
   ```

3. Or start the dev server:
   ```bash
   npm run dev
   ```

   This opens http://localhost:5173. Note that `bash scripts/build.sh` must be run at least once first to generate the WASM artifacts in `dist/pkg/`.

## Architecture & Design

```
┌─────────────────────────────────────────────────────────────────────────────────┐
│  Browser Frontend (Vite + Monaco Editor)                                        │
│                                                                                 │
│   • Client-Side "Mini-LSP" (src/main.js & src/utils.js)                         │
│     - Tree-Sitter AST Tokenizer (web-tree-sitter + tree-sitter-melbi.wasm)      │
│     - Custom Semantic Syntax Highlighter                                        │
│     - Monaco Providers: Hover, Autocomplete, Diagnostics                        │
│     - Shared VS Code Language Config (copied from ../vscode/)                   │
└─────────────────────────┬───────────────────────────────────────────────────────┘
                          │
                          ▼ calls evaluate() / hover() / completions()
┌─────────────────────────────────────────────────────────────────────────────────┐
│  WASM Worker Engine (playground/worker)                                         │
│                                                                                 │
│   • Compiled to WASM via wasm-bindgen (playground_worker_bg.wasm)               │
│   • Pure Rust melbi-core (parser, type analyzer, bytecode VM execution)         │
│   • Returns structured JSON evaluation results & diagnostics                    │
└─────────────────────────────────────────────────────────────────────────────────┘
```

### Key Design Decisions

1. **Why the native LSP (`melbi-lsp`) is NOT used**:
   Native `melbi-lsp` uses `tokio` and native C tree-sitter bindings over `stdio`, which are unavailable in a browser environment. Instead of running `melbi-lsp`, the playground implements a **client-side mini-LSP in JavaScript**.

2. **Client-Side "Mini-LSP" (`src/main.js` & `src/utils.js`)**:
   * **Semantic Syntax Highlighting**: Uses `web-tree-sitter` and `tree-sitter-melbi.wasm` to walk the AST in JS (`buildTokensFromTree`), mapping grammar scopes dynamically to Monaco tokens and theme colors.
   * **Monaco Language Providers**: Registers Monaco providers for Hover types, Autocomplete suggestions, and Diagnostics (squiggly lines) generated by `melbi-core`.
   * **VS Code Language Config**: Copies `language-configuration.json` directly from the [`vscode/`](../vscode/language-configuration.json) extension to configure bracket matching, auto-closing pairs, comment formatting, and indentation rules.

3. **WASM Evaluation Worker (`playground/worker`)**:
   * Rust crate compiled to WebAssembly via `wasm-bindgen`.
   * Wraps `melbi-core` to execute code, compute types, and produce diagnostic spans directly in the browser with zero network latency.

4. **Build Pipeline (`playground/scripts/build.sh`)**:
   * Compiles `tree-sitter-melbi.wasm` using Tree-sitter CLI.
   * Builds `playground/worker` with `wasm-pack` (`wasm-opt` enabled).
   * Bundles assets using **Vite** into `dist/`.

## Playground Versions

The playground has three versions:

- **index.html** - Main playground with editor and output
- **tutorial.html** - Interactive tutorial with step-by-step lessons
- **embed.html** - Minimal embeddable version

All versions are built from the same codebase and deployed together.

## Worker API

The WebAssembly module exposes the Melbi evaluation engine:

- `evaluate(source: &str)` → returns value + type or structured diagnostics

Responses follow a `{ status: "ok" | "err", ... }` envelope for structured error handling.

This crate reuses `melbi_core::api::Engine`, ensuring results match the CLI tools byte-for-byte.
